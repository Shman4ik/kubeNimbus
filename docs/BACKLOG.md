# kubeNimbus backlog

The queue `/backlog-cycle` works from. Everything below is either **validated by
a human and ready to build** (the Ready table) or **waiting for a human to
validate it** (the Inbox). The loop may only take work from Ready — that gate is
deliberate and is the one rule of this file.

## Config

The cycle re-reads these each run, so changing one here changes the loop's
behaviour on the next tick.

| Key | Value | Meaning |
|---|---|---|
| `AUTO_PR` | `yes` | On PASS, push the branch **and** open a pull request against `main`, following `.github/PULL_REQUEST_TEMPLATE.md`. Set to `no` to push the branch only. |
| `MAX_FIX_ROUNDS` | `2` | Verifier FAIL → implementer fix rounds before the item is marked `blocked`. |
| `RESEARCH_EVERY` | `5` | Cycles between competitor-research runs. |
| `READY_POOL_MIN` | `5` | Research also runs whenever Ready drops below this. |

**Status:** `inbox` → `ready` → `in-progress` → `needs-fix` → `done`, or
`blocked` / `rejected`.
**Priority** is `P0`–`P3` and is set **by a human only**. An item with no
priority is not ready, whatever its status column says.
**Size** is `S` (a session), `M` (a day), `L` (multi-session, wants its own
design pass first).
**Rec** is the recommendation this file was drafted with — a starting point for
your prioritization, not a decision.

## Inbox — needs your validation and priorities

**Every row's `Prio` column now carries a feasibility mark**, added by the 2026-08-19
review, because the same question was being re-answered from scratch at each refill of
Ready. The vocabulary is small and each mark means one thing:

- **`can do here`** — an agent container can take it from nothing to a verified,
  pushable change: build, both TUnit suites, the screenshot harness, the linux-x64
  NativeAOT publish and `--smoke-test` under Xvfb are all it needs. This is the Ready
  table's entry test, so these rows are promotable without further thought.
- **`needs a live cluster`** — the acceptance criterion names a real API server.
  Registries have been unreachable from these containers in most sessions, so this is
  the largest single bucket and the reason section A keeps growing.
- **`needs a Windows box` / `needs a Mac` / `needs a desktop terminal emulator`** — a
  platform nothing here can stand in for.
- **`needs a human`** — a decision, an account, a certificate, a repository permission
  or an issue on somebody else's project. Each says which in place.
- **`→ Ready`** — promoted, and in the table above.
- **`done <commit>`** — shipped; the row is kept for the evidence it carries.

A mark is about *reachability*, not worth: several `needs a live cluster` rows are P1
and matter more than anything currently promoted. It only says who can start them.
