# Accessible names come from the tooltip

> Part of the kubeNimbus engineering contract, moved out of `CLAUDE.md` so it loads only when relevant. Same discipline applies: keep it current in the PR that changes what it describes.

Windows UI Automation (and so a screen reader, and `scripts/qa-ui.ps1`) asks every control for a name. A button that draws only an icon has none and reports its content's type, `Avalonia.Controls.PathIcon`; a list item whose content is a view model reports that type's name; the command palette's rows used to report a record's property dump. ENG-4 and ENG-47 recorded it, and the 0.5.1 release pass counted it: every icon button in the command bar, every sidebar row, every Applications row and every switch on the preferences page.

The rules:

1. **The tooltip is the one place the words are written.** Every icon-only control already says what it does in a tooltip, so `AutomationNames` (installed from `App.Initialize`, next to `ToolTipHitTesting`, so the screenshot harness gets it too) copies it into `AutomationProperties.Name` whenever a tooltip is set or changes, bindings included. It keeps the first clause (text after an em dash, a colon or a full stop is explanation) and drops a trailing parenthesis, which is the shortcut. A name written by hand in markup always wins: a hand-written name is a decision, a derived one is a default. A button whose content is a string, and any control with no tooltip, is left to name itself from its own text; a text box with no tooltip takes its placeholder.
2. **Do not write a second sentence for a control that has a tooltip.** Add the tooltip. A control with neither gets an `AutomationProperties.Name` (a literal for a control with no visible words, such as the switcher's `+`) or `AutomationProperties.LabeledBy` pointing at its visible label (the port-forward and replica number boxes), so the label stays the one copy.
3. **A list item names itself through its content's `ToString()`.** `ApplicationRowViewModel` overrides it ("crashloop, Degraded, demo-broken. Crash-looping (exit 1)"), and the sidebar rows bind `AutomationName` (the kind, and its API group when another kind shares the name). Computed on demand, so a row that changes in place never reads stale.
4. **The preferences cards are named from their labels.** `AutomationNames.NameCardControls` gives the switch, drop-down or number box at the right of each card the text of the label at its left, once, when the page is attached. It walks the logical tree: the page is tabs (2026-10), and only the tab on screen has visuals when the page loads, so a visual walk left the other three tabs' switches unnamed. The harness's `ux-preferences-tabs` checks a control on a tab that was not shown at load.
5. **Template parts are named by what they do**: the overlay and spinner buttons (`PART_CloseButton`, `PART_IncreaseButton`, `PART_DecreaseButton`) in one place rather than in every theme that restyles them.

`AutomationChecks` in the screenshot harness walks the automation peers of every scenario's window the way a UI Automation client does. It fails the run on any peer that throws, and on any operable control (button, item, edit, drop-down, switch) whose name is empty or a type name, so a new icon button with no tooltip and no name fails the render step the day it is added. It is a check on the names the app sets, not on what the Windows provider reports: a headless peer is not that provider, and a name that looks fine there can still come back empty from UIA, which is why the check that counts for a release is `scripts/qa-ui.ps1 dump` against a real build, with `<unnamed>` as what to look for. The 0.5.1 pass did that on the NativeAOT build for the command bar, the sidebar (Argo, Helm and both Widget rows included), the Applications rows, the dock tabs and the palette.

What is not covered, stated: the inner text box of a number box (a template part of a control that is itself named, skipped by the check), the DataGrid's cells and rows, which UIA reads through their cells, the dock tabs themselves, which are not controls (ENG-54), and the duplicate name `Close` shared by the window's caption button and the action strip's Close button, which made a name-based QA script close the app.
