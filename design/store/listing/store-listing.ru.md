## Short description

```text
Быстрый бесплатный клиент Kubernetes (K8s) с открытым кодом для Windows. Находите неработающие приложения, следите за логами подов, смотрите CPU и память без установки Prometheus, открывайте терминал в контейнере и правьте YAML. Вход в AWS EKS, Google GKE и Azure AKS работает через ваш kubeconfig. Нативное приложение без телеметрии, учётной записи и подписки.
```

## Description

```text
kubeNimbus — быстрый бесплатный настольный клиент Kubernetes для Windows. Найдите неработающее приложение, поймите, почему оно падает, и откройте нужные логи, не выходя из одного нативного приложения. Без телеметрии, учётной записи и подписки.

Найдите проблему
Раздел Applications первым показывает то, что требует внимания. У каждого приложения Argo CD и у каждой рабочей нагрузки, которую не отслеживает ни одно приложение, есть вердикт о состоянии и причина в одну строку, взятая из собственного статуса кластера. Откройте приложение, чтобы увидеть факты, на которых основан вердикт: его поды, хронологию и последний запуск упавшего пода. Полный обозреватель Resources — в один клик.

Подключайтесь тем, чем уже пользуетесь
kubeNimbus читает все контексты из $KUBECONFIG и ~/.kube/config, включая вход через exec-плагины для AWS EKS, Google GKE и Azure AKS, и кластеры за прокси. Истёкшая сессия возобновляется без закрытия вкладки. При ограниченных правах kubeNimbus показывает то, что вам можно читать, и сообщает, что прочитать не удалось. Открывайте несколько кластеров во вкладках, выбирайте несколько пространств имён или используйте общий список по всем подключённым кластерам. Production, staging и development выделены разными цветами. Пароли, токены и сертификаты никогда не копируются в хранилище приложения.

CPU и память: ничего устанавливать не нужно
kubeNimbus читает API метрик, который уже отдаёт ваш кластер (metrics-server). Списки подов и узлов показывают текущее потребление CPU и памяти, детали пода рисуют график за последние 30 минут вашего сеанса, а список Nodes показывает занятую и запрошенную ёмкость. Prometheus и агент внутри кластера не нужны. В кластере без metrics-server эти столбцы скрываются, а не показывают ошибки.

Исследуйте, не выходя из приложения
• Живые списки ресурсов для каждого вида, который отдаёт ваш кластер, включая пользовательские ресурсы. Списки обновляются через watch в Kubernetes, с поиском, сортировкой и выбором столбцов.
• Логи подов: follow, поиск, регулярные выражения, фильтры по уровню, переход к ошибкам, логи предыдущего контейнера для CrashLoopBackOff и все поды рабочей нагрузки в одном потоке с цветовой маркировкой.
• Детали пода: переменные окружения с подставленными значениями из ConfigMap и скрытыми значениями из Secret, пока вы не попросите показать их; условия, пробы и QoS; CPU и память во времени.
• Настоящий терминал для exec: vi, top и mc отображаются правильно, а Ctrl+C доходит до контейнера. Если удобнее, открывайте exec или оболочку узла в своём терминале.
• Port-forward для пода или Service, открытие локального адреса в браузере и работающие пробросы после закрытия их вкладки в нижней панели.
• Панели Service, Ingress и NetworkPolicy, которые объясняют, может ли трафик дойти до подов.
• Детали узла: запас между доступным и запрошенным, события и измеренная нагрузка. Полоса ёмкости показывает занятые и запрошенные CPU и память по всем узлам.

Проверяйте изменения до применения
• Правка YAML с server-side apply, строгой проверкой полей и предпросмотром dry-run: он спрашивает у API-сервера, что сделает изменение, до того как оно будет применено.
• Вставьте манифест, чтобы создать новый ресурс. Выберите несколько ресурсов и удалите их разом с одним подтверждением.
• Scale, rollout restart, delete, cordon и drain. Перезапуск, drain и удаление выполняются только после подтверждения, и приложение заранее называет объект; удаление в production-кластере всегда спрашивает, в остальных подтверждение удаления можно отключить. Scale сначала спрашивает новое количество.

Инструменты Kubernetes в одном месте
• Просматривайте релизы Helm, значения, манифесты и историю ревизий прямо из кластера, бинарный файл Helm не нужен.
• Просматривайте Applications, ApplicationSets и AppProjects Argo CD; запускайте sync, refresh или прерывайте идущий sync через подключение к Kubernetes, без повторного входа.
• Проверка доступа RBAC: что мне здесь можно, откуда берётся доступ ServiceAccount и кто может сделать X?
• Ctrl+K находит команду, Ctrl+P переключает кластеры, F1 показывает все сочетания клавиш. Есть светлая и тёмная темы.

Попробуйте до подключения
Выберите "Explore demo cluster" на первом экране. В приложении есть примеры приложений, подов, логов и сведений о ресурсах, для которых не нужны кластер, учётные данные и сеть. Примеры везде помечены; exec, port-forward и применение YAML требуют настоящего кластера. Интерфейс приложения на английском языке.

Ваши кластеры остаются вашими
kubeNimbus — самодостаточное приложение NativeAOT, устанавливать среду выполнения .NET не нужно. Оно подключается только к кластерам, которые вы открываете, и само не собирает аналитику, не отправляет отчёты о сбоях и не проверяет обновления. Обновлениями занимается Microsoft Store. Учётные данные остаются в вашей цепочке kubeconfig; в политике конфиденциальности перечислены локальные файлы настроек и сеанса.

kubeNimbus бесплатен, его исходный код открыт под лицензией MIT: https://github.com/Shman4ik/kubeNimbus

От того же разработчика: pgNimbus, клиент PostgreSQL, сделанный так же, бесплатный и в Store: https://apps.microsoft.com/detail/9N6SZT42XJ24
```
