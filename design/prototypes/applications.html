Что проверяет прототип

  • Первый экран — список приложений (твой ответ 3). Нездоровые сверху; вторая строка — причина одной фразой, детерминированно из статусов и events.
  • Приложение = Argo Application; без Argo — Deployment / StatefulSet / Job (группа «Not in Argo CD»). Состав — из ссылок в spec, а не из меток.
  • «Deployed < 1 h» — сценарий «после деплоя всё зелёное?» одним кликом.
  • Что поменялось — без своей истории и без API Argo: status.history (SHA и время), разница pod template между старым и новым ReplicaSet, events Application. Ссылка на compare коммитов открывает git-хостинг.
  • CrashLoop — сразу выбран падающий pod и его последний запуск, в конце строка с exit code.
  • Логов нет — отдельное состояние с причиной (fraud-detector, settlement-batch).
  • selfHeal — Edit YAML предупреждает, что Argo откатит правку, и ведёт в Git.
  • URL Argo UI для «Open in Argo CD» можно взять из argocd-cm → data.url, если его разрешено читать.

Открытые вопросы

  • A или B — поды списком или дерево как в Argo? Переключатель вверху.
  • Что вверху страницы — здесь «What's wrong» и лента за час. Или логи сразу на всю высоту?
  • Кластеры — вкладки оставлены как сейчас. Альтернатива: один список по всем кластерам с колонкой Cluster.
  • Режим Resources — переключатель в command bar или просто drill-down со страницы приложения?

Что попробовать

  • Открыть checkout: падающий pod, нехватка quota, что поменялось в шаблоне.
  • Открыть fraud-detector: нет логов, почему pod не запланирован.
  • Нажать Edit YAML… на Argo-приложении.
